# Meta Strategy — チャット全体を俯瞰する提案ストック

## 目的

特定のプロジェクトの進捗管理やタスクの再配分ではなく、ユーザーとChatGPTの活動全体を一段高い視点から再評価し、興味自体を豊かに広げる。事業だけでなく、趣味・好奇心・文化・娯楽・暮らしのアイデア、個人の日常、未経験の分野への偶然の出会い、そして「今やらなくていいこと」まで扱う。

- **入口**: My Portal `/meta`
- **正本**: `metaStrategyProposals`（既存 `documentDb` を使用し、Firestore/Turso両バックエンドに適応）
- **チャット連携**: MCP `meta_proposal_list`, `meta_proposal_get`, `meta_proposal_create`, `meta_proposal_feedback`
- **Web UI**: 認証済み `/api/agent-ideas?resource=meta_proposals` と `meta_proposal_feedback`
- **責務境界**: Agent HQ Work Items / Keywords ideas / Portal Boards / human Thinking Spaces と別の記録

## 提案の射程 — プロジェクトも私生活も、両方が本質

これは「次のタスク」を並べるだけの機能ではない。**既存プロジェクトの継続・改善・撤退・新規企画の提案を必ず探索対象に残した上で**、ユーザーが普段自分から探さない面白いもの、好奇心を広げる切り口、生活の別の過ごし方も届ける。どちらか一方への置き換えではない。仕事・収益・開発を軽視せず、同時に人生の話題を仕事へ回収しない。

同じ台帳の `lens` で視点を区別する（`category` は自由記述でテーマの具体性を保持）:

- `curiosity`（興味を広げる）: 映画・音楽・本・ネット文化・科学・歴史・社会・アート・スポーツ・ゲーム・場所・技術的好奇心・全く未知の領域など。既知の興味の隣接分野だけでなく、遠い分野への橋をかける。
- `personal`（個人的なこと）: 日常の楽しみ方、時間の使い方、余暇、習慣、体験、学び方、人との接し方、生活上の小さな工夫。無理に改善課題にしない。敏感な個人属性や健康・人間関係の詳細を根拠なく推測しない。
- `projects`（活動・仕事）: 仕事、開発、事業、学習プロジェクトの方向転換や投資配分。細かなタスク進捗は各Operatorへ。
- `cross-cutting`（横断的な発見）: 複数分野を結び直す視点、活動の意味の問い直し、価値観や優先順位を広げる問い。

**毎回の発想ルール**: (A) 既存・新規プロジェクトや事業について、成果・停滞・方向性の変更、新しい企画機会を独立して考える。(B) 既存プロジェクトと無関係な興味・余暇・暮らしについて、何が純粋に面白いかを独立して考える。(C) その間を横断する意外なつながりも探す。AもBも継続対象として外さない。各候補は同じ提案台帳に保存するが、後付けで仕事化しない。個人の過去チャットを単なるビジネス機会データとして扱わない。

**偏り対策**: 最近の提案と採否を読み、直近の `lens` の偏りを確認する。業務提案ばかりなら `curiosity` と `personal` に追加の探索を行い、逆に趣味提案ばかりなら `projects` の探索を強化する。各実行で両方の領域を検討しつつ、毎回の採用件数や比率を機械的に固定しない。プロジェクトの重要な機会や障害も、個人的に面白い発見も取りこぼさない。

提案の根拠は、ユーザーが実際に話したことと、そこからの仮説、外部で確認した文化・作品・事実を区別すること。未確認の趣味を既成事実にしない。健康・性的指向・信条などのセンシティブな情報を、ユーザーが許可しないままプロフィールや推薦文の根拠として保存しない。本人に対して人格診断をしたり、過剰に親密な呼びかけをしたりしない。

## 提案の品質

1. 事前に `world_map_get`, `meta_proposal_list` と必要な Context / 担当システムの正本を読む。
2. ChatGPT の全会話ログが自動的に読み出せるとは仮定しない。利用できた過去の会話・記憶・Contexts・接続先だけを明示する。最近の発言を過去の優先順位より重視するが、ユーザーが却下済みの案は自動復活させない。
3. 「今すでにやっていることの進捗」ではなく、活動の前提を問い直すこと、分散した課題を抽象化すること、隠れた時間コストや実機会を発見することを優先する。
4. 提案は title / ideaKey / summary / reason / nextStep / lens / category / priority / evidence / uncertainty / context の形で保存する。根拠は日時・実際の参照元・観察内容と、そこからの推論を区別する。アクセスできていないものを観察済みと扱わない。
5. `ideaKey` は同一テーマで安定させる。重複作成時はユーザーの評価、却下理由、採否状態を上書きしない。**提案の採用は実装・配信・公開の包括許可ではない。**
6. 毎回大量に埋める必要はない。新しい価値や観察がなければ追加0件でもよい。件数ではなく提案の精度を追う。ユーザーの見送り理由は次回の発想への負の制約として使用する。

## 継続実行（2026-10-16移管後の正本）

新設されたAgent HQの軽量「定期ジョブ」には、専用ジョブ **`meta-personal-strategy-discovery`** を保存している。ChatGPTの **「Agent HQ 定期ジョブ」** という既存スケジュールタスク（04:30 / 10:30 / 16:30 JST）を起動枠として共用し、メタ提案は **毎日16:30 JST** のみ実施する。

- 管理画面: My Portal `/dashboard` → 「定期ジョブ」。
- **ジョブ正本**: My Portal MCP `routine_job_list`, `routine_job_upsert`。
- **実行契約**: `routine_job_due` → `routine_job_claim`（同一日/枠で一度だけ）→ ジョブ内の最新instructionsを実行 → `routine_job_finish`（必ず成功/失敗と検証情報を記録）。毎回最大3ジョブまでの既存ランナーを利用。
- ジョブは既存・新規プロジェクトの企画と個人の興味・暮らしの推薦の双方を検討し、重複や過去の採否理由を照合して、良質な新提案を最大3件まで `meta_proposal_create` で台帳へ保存し、`meta_proposal_get` で確認する。
- **旧方式は停止**: ChatGPTの「Agent HQ 共通ディスパッチャー」（09:00/15:00/21:00 JST）は育成組織のManager/WorkerとOutcome Auditの担当のみ。15:00のMeta Strategy処理は取り除いた。ユーザーが求める個人向け提案をHQのManager Jobへ紛れ込ませない。
- ChatGPTスケジュールタスクの有効枠を新規には消費しない。独立Sites Operator/SEO・市場探索・SNS下書き補充の実行設定には干渉しない。
- Meta StrategyのMCP toolがScheduled Task環境で見えない場合、他DBへ代替保存したり架空の成功を記録したりしない。`routine_job_finish(status:'failed')` に正確な障害を残す。新しいツールの公開状態と、専用ランナーからの実保存・読み戻しは、実行後の履歴で検証する。

ChatGPTの全チャットを常時網羅しているとは仮定せず、利用可能な会話文脈・記憶・Contexts・一次情報のみを根拠にする。本人の採用・見送り判断を書き換えない。提案の採用は実装・公開・投稿・購入等の包括許可ではない。

## UX

主画面では領域（興味を広げる/個人的なこと/活動・仕事/横断）、優先度、ステータス、根拠、留保、まず試すならを俯瞰し、気になる・採用 / 見送り / 検討中 / 完了 と自由記述理由を保存する。詳細を開かなくても採否を付けられる。レビュー履歴は提案IDと revision で保護する。

今後の改善候補: 完了した提案の追跡結果、テーマ類似の統合、前回のレビュー境界に基づく差分収集。初期実装で巨大なAI自動探索パイプラインを増やさない。
